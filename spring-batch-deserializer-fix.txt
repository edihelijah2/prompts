In this Spring Boot 4 / Spring Batch 6 project, jobs fail on restart with `Failed to deserialize object` because the default `DefaultExecutionContextSerializer` rejects any class not on its `ObjectInputFilter` allow-list (CVE-2026-47878 hardening). First find every custom (non-JDK, non-`org.springframework.batch`) type that gets stored in a job or step `ExecutionContext`, including nested field types, enum values and collection elements, and derive the narrowest package patterns that cover them. Then add a custom `ExecutionContextSerializer` bean, wired into the job repository, that extends the default allow-list with only those packages and keeps the trailing `!*` reject-all, and verify that an existing context containing those types deserializes and that classes outside the allow-list are still rejected.
